# Ключ подписи приложений — как хранить и зачем

## Коротко и самое важное

Ключ подписи лежит здесь:

```
~/child-keys/child-release.jks      — сам ключ
~/child-keys/key.properties         — пароли и путь к нему
```

**Потеря этого ключа означает, что вы больше никогда не сможете обновить
приложение у семей и водителей.** Android не примет обновление, подписанное
другим ключом: для телефона это будет чужая программа. Придётся выпускать
новое приложение, а всем пользователям — удалять старое и ставить новое
вручную. На пилоте с 15 семьями это неприятно, на сотне — катастрофа.

Ключ создан 23 сентября 2026 года и действует до 2056 года.
Отпечаток (SHA-256), по нему всегда можно проверить, тот ли это ключ:

```
49:60:83:64:C3:EF:3B:F2:20:3B:3C:B3:F0:66:38:0C:2A:F0:67:4F:A6:F3:03:B5:5C:78:AF:0F:57:5D:65:B8
```

## Что сделать прямо сейчас (10 минут)

Нужно **три копии в разных местах**. Одна копия на рабочем ноутбуке — это
не копия, а единственный экземпляр.

### 1. Копия в менеджере паролей

Если пользуетесь 1Password, Bitwarden или подобным:

1. Создайте запись «Child — ключ подписи Android».
2. Приложите файлом `~/child-keys/child-release.jks`.
3. В поля пароля скопируйте значения `storePassword` и `keyPassword`
   из `~/child-keys/key.properties` (они одинаковые).
4. В заметку скопируйте отпечаток SHA-256 отсюда.

Это лучший вариант: шифрование, синхронизация, доступ с любого устройства.

### 2. Зашифрованный архив в облаке

```bash
cd ~
zip -r -e child-keys-backup.zip child-keys/
```

`-e` спросит пароль для архива — придумайте отдельный и **сохраните его
в менеджере паролей**, иначе архив тоже станет бесполезен. Готовый
`child-keys-backup.zip` положите в Google Drive, Яндекс.Диск или другое
облако, которым пользуетесь.

### 3. Физическая копия

Тот же `child-keys-backup.zip` — на флешку, и флешку не в сумку с
ноутбуком, а домой или в сейф. Облака блокируют аккаунты, ноутбуки
ломаются и теряются; флешка в ящике стола переживёт и то, и другое.

## Чего делать нельзя

- **Не коммитить ключ в репозиторий.** Репозиторий с кодом публичный;
  ключ в нём — это возможность для любого выпустить поддельное обновление
  вашего приложения. В `.gitignore` защита уже стоит, но проверяйте.
- **Не пересылать ключ в мессенджерах** обычным сообщением.
- **Не менять пароль** у существующего ключа «для порядка»: если
  ошибётесь, восстановить будет нечем.

## Как проверить, что копия рабочая

```bash
keytool -list -v -keystore /путь/к/копии/child-release.jks -storepass ПАРОЛЬ | grep SHA256
```

Отпечаток должен совпасть с тем, что указан выше. Сделайте это один раз
после создания копий — чтобы не выяснить через год, что в архиве пусто.

## Если ключ всё-таки потерян

Честно: восстановить его нельзя. Порядок действий будет такой —
новый ключ, новый идентификатор приложения, новая установка у всех
пользователей вручную. Google Play частично закрывает эту проблему
(Play App Signing хранит ключ на стороне Google), и при публикации
в Play мы этим воспользуемся. Но APK с сайта, который мы раздаём
водителям и семьям напрямую, зависит только от этого файла.

## Как этот ключ используется в сборке

`apps/*/android/app/build.gradle.kts` читает `~/child-keys/key.properties`.
Если файла нет (чужая машина, CI), сборка не падает — используется
отладочная подпись, и такой APK годится только для тестов.

Релизные APK собираются так:

```bash
cd apps/parent && flutter build apk --release --split-per-abi --dart-define=FLAVOR=prod
cd apps/driver && flutter build apk --release --split-per-abi --dart-define=FLAVOR=prod
```

Готовые файлы — в `build/app/outputs/flutter-apk/`. Их три, по одному на
архитектуру процессора: телефон скачивает только свой (17–21 МБ вместо
одного файла на 50+ МБ). Для раздачи «с сайта» обычно нужны
`app-arm64-v8a-release.apk` (почти все современные телефоны) и
`app-armeabi-v7a-release.apk` (старые).
